通用 UI 规范

覆盖除游戏桌之外的所有界面：钱包、大头菜、股票、交易行、帕鲁、通知、设置、管理后台。统一 UI/UX 逻辑和视觉语言。

00 · Principles

五条原则

当你拿不准时，回头看这五条。它们凌驾于任何具体规则之上。

01
密度优于舒适
这是个交易所。用户来看数字，不是来休息。每一个 px 要有理由。
02
功能性克制
一个 accent、一个字体、一套语义色。装饰是负债。
03
数字用 mono
所有金额、ID、百分比用等宽字体 + tabular。千万不要用 sans 写数字。
04
吉祥物有克制
🐻 只在空态、mascot 场景和 title 前品类色块里出现。别在 body 里撒 emoji。
05
移动端同等重要
每一条规则都要有移动端版本。不是"先桌面再响应式"——是两条轨道并行。
01 · Layout

布局与容器

三档页面宽度。选对档位比微调 margin 更重要。

三档 tier

Narrow · 640px — 单对象编辑。登录、转账、钱包、设置·安全。

Medium · 860px — 一个对象 + 它的列表。大头菜、股票、帕鲁、通知。

Wide · 1120px — 多列 / 多对象 / 数据表格。交易行、管理后台、开发者工具。

选型：一次只看一个对象 → narrow。看对象 + 统计 → medium。比较多对象 → wide。不要更宽。

1 · Header

  • 高 48px。H1 是 24/700/-0.01em。
  • 左侧可选 28×28 品类色块（emoji 在 accent-tint 上）。
  • 右侧 1–3 个操作按钮。主 CTA 最右。

  • 没有副标题。需要说明用 title 旁 ? tooltip。

2 · Sub-nav（按需）

  • Breadcrumb — ≥3 层才出现。
  • Tabs — 同对象不同视图（概览 / 交易 / 设置）。2px accent 下划线。
  • Segmented — 小范围切换（24h / 7d / 30d）。右上角。
  • Filter bar — 搜索 + select。列表正上方。
  • 同时只能有一种 sub-nav。

3 · Content 顺序

  • Hero（首屏最重要的数字）
  • 快捷操作（3–5 按钮）
  • 列表 / 表格（主体）
  • 次要数据（底部 stat grid）

4 · Footer（按需）

  • 列表 >20 条 → 加载更多 ghost button，居中。
  • Data table → 底部分页条。
  • 底部为移动端 tabbar 留 80px 呼吸。

Debounce / Throttle 时长表

凡是「用户还在操作就不该立刻发请求」的场景，必须走统一延迟。不要自己拍脑袋写 200/500。

场景策略延迟说明
搜索框（列表筛选）debounce300ms回车立即触发，清空立即重查
自动补全 / 命令面板debounce150ms要的是即时反馈
字段级远端校验（用户名查重）debounce500ms远端请求，宁等勿频
字段级本地校验（格式 / 长度）无0blur 时触发，见 §表单
筛选 / 排序 / 切 tab无0离散操作，立刻触发
滑块 / range（影响图表）throttle100ms拖动节流，松手时 fire 最终值
resize / 滚动位置上报throttle200ms用 rAF 包
富文本 / 草稿自动保存debounce1500ms键入停 1.5s 后静默保存
虚拟列表 / 无限滚动throttle100ms到底触发，下次 100ms 后可再触
输入时千分位格式化无0每次键入即格式化

实现要求

  • 统一 hook / util：useDebounced(value, delay) + debounce(fn, delay)，全站走同一个。
  • 取消前一次：新输入必须用 AbortController 取消在 flight 的请求，不只是忽略响应。
  • Loading 延迟显示：skeleton / spinner 显示在 debounce 结束后的真正请求期间。键入过程中不闪 loading。
  • 清空立即触发：点 × 清空搜索框 → 不走 debounce，立刻重查。
  • 首字符仍走 debounce：不要「第一下立刻查，之后才 debounce」。行为要可预测。
  • 回车跳过 debounce：按回车 = 「现在就要」，立即 fire + 取消待执行。
04b · Query Bar

列表查询条 · 搜索 / 筛选 / 排序

Raid · Market · 订单 · Pal 背包 · 交易记录——凡是列表 ≥ 20 行，就走这一套。一个组件，一种顺序，一种行为。

锚点位置

  • 永远贴在列表正上方，margin-bottom: 12px。不要飘、不要吸顶、不要进 drawer（移动端除外，见下）。
  • 查询条的左右边界对齐列表，不是页面容器。让人一眼看到"这些控件管的是下面这张表"。
  • 页面标题 → 结果计数 → 查询条 → 列表。顺序固定。

① 搜索框

  • 最左，flex: 1，最小 220px。永远最宽的那个。
  • 高度 36px，border-radius: 8px。左侧 🔍 图标，右侧输入清空 ×。
  • Placeholder 具体："搜索名字、ID、稀有度…"，不写"搜索"。
  • Debounce 300ms。Enter 立即触发。点 × 立即重查（不 debounce）。
  • 输入时不闪 loading；debounce 结束后在列表上方出 skeleton / progress。
  • 支持 / 快捷键聚焦（见 §13）。

② 筛选 select

  • 高度 36px，padding: 0 12px，背景同 bg-primary。
  • 标题写字段名：「稀有度」「状态」「阵营」——不写「选择筛选」。
  • 已选中时标题变为值："稀有度：传说" + accent 色边框。
  • 同页筛选上限 4 个。超过塞进「更多筛选」popover。
  • 改变 → 立刻查。不要「应用」按钮。不要 debounce。
  • 多选下拉：复选框 + 底部「清除」「完成」。打开时不查，关闭时一次性 fire。

③ 排序

  • 一般走排序 select：「价格 ↓ / 价格 ↑ / 最新 / 战力 ↓」。默认值进 placeholder。
  • Data table（多列）的排序走表头点击，不放 select；避免双真相。
  • 排序方向用 ↑ / ↓，不用 asc/desc 文字。
  • 默认排序要合理：Market 按"最新挂单"；Raid 按"剩余时间"；订单按"创建时间 ↓"。

④ 结果计数

  • 右上角："共 1,248 条 · 显示 25"。mono，secondary 色。
  • 筛选后变："筛选后 82 条"，和总数分开写。
  • 0 结果：走 §11 空状态，不显示表头。
  • 超过 10,000 条时写 "10,000+"，不要精确数字（查不动也没意义）。

已选筛选 · Chip 行

  • 筛选一旦有值，查询条下方 8px 出 chip 行：字段 = 值 ×。
  • Chip 高 24px，border-radius: 999px，accent-tint 背景 + accent 文字。
  • 点 × 只清这一项。≥2 个 chip 时末尾跟「清除全部」文字链接。
  • Chip 内的值走用户语言（见 §15）：写「传说」不是「legendary」；写「在售」不是「status=listed」。
  • 搜索关键字不上 chip——它在搜索框里已经可见了。

URL 同步（不可省）

Example /market?search=fire&rarity=legendary&rarity=epic&status=listed&sort=price:desc&page=3
  • 搜索 / 筛选 / 排序 / 分页全部写 URL。刷新、分享、后退都不丢。
  • 默认值不写入 URL，保持干净。例：默认排序、page=1。
  • 多值用重复 key：?rarity=legendary&rarity=epic，不用 CSV。
  • 首次进页面：先读 URL，再发请求。不要先空查一次再回填。
  • 完整约定见 §12 Routing & URL。

Saved Views（可选 · 常用列表加）

  • 用户把一组搜索+筛选+排序存为命名视图："我的在售" · "未领奖励" · "高胜率 Raid"。
  • 视图条在查询条上方作为 segmented tabs：所有 · 我的在售 · 未领奖励 · + 新视图。
  • 切换视图 = 写一组 query 参数。视图本身不在 URL 里；URL 永远是参数源头。
  • Raid · Market · 订单至少配「系统默认 2–3 个视图」。新用户进来就有用。

移动端（< 720px）

  • 搜索框独占一行，100% 宽度。
  • 第二行：「筛选 (2)」按钮（括号数字 = 已选筛选数） + 「排序：价格 ↓」按钮。点开 右侧 drawer。
  • Drawer 里分组所有筛选 + 排序，底部粘顶条「清除」「查看 82 条结果」。
  • Chip 行照样在列表上方，可横向滚动。
  • 结果计数移到列表第一行之前、chip 之下："82 条结果"。

加载与空态

  • 查询中：列表上方 2px 进度条（accent 色），不动原行。滚动位置保留。
  • 首次无结果："没有匹配的结果" + "清除筛选" 按钮。不要只展示 "Empty"。
  • 筛太狠 0 结果：提示最近一个被加的筛选："去掉稀有度=传说可看到 48 条"（智能降级，可选）。
  • 错误：列表位置换成错误卡 + "重试"，查询条保留可用，允许用户改参数再试。

Do / Don't

Do
  • 筛选改变立刻重查
  • 搜索 placeholder 写清搜哪几个字段
  • 已选筛选用 chip 可见、可一键删
  • URL 里能看出当前视图
  • 默认排序要"符合直觉"（Market = 最新，Raid = 最紧迫）
Don't
  • 放"应用筛选"按钮
  • 搜索框 placeholder 只写"搜索"
  • 把排序和筛选混成一个 select
  • 表头排序 + 顶部排序 select 同时存在
  • 筛选值用字段枚举：status=active 而不是"在售"
  • 结果数藏在分页器里，用户第一眼看不到
04c · Row Actions

行内操作 · Inline / Popover / Drawer / Modal

列表行上常带操作：卖出 · 平仓 · 上架 · 撤单 · 领取 · 上阵。这些操作怎么出现、在哪展开、用哪种容器——有一套固定决策树，别每个页面各自发明。

决策树：这个操作用什么容器？

按三个问题走
Q1 操作需要用户输入参数吗？（数量、价格、备注…） 否 → Q2 是 → Q3 Q2 操作是否破坏性/大额/不可逆（见 §09 危险分级）？ 否 → 行内按钮，点一下直接执行（带 toast + 撤销） 是 → ConfirmDialog (Modal)，问一句再执行 Q3 输入是1–2 个字段且能 30 秒内填完？ 是 → Popover 紧贴行展开（就地操作，不离开列表） 字段较多 / 需要预览 / 有多步 → Drawer（右侧滑出，列表仍在左侧可见） 跨页流程 / 创建新对象 → Route 页（/orders/new，不走 modal）

四种容器的使用边界

容器触发何时用典型例子
行内按钮 直接点击 零输入 · 可逆 · 瞬时完成。执行后 toast + 5s 撤销。 领取奖励 · 收藏 · 上阵 / 下阵 · 应战 (一键加入)
Popover 点行内按钮 →
锚定展开		 1–2 个字段，就地改就地提交。不离开列表。宽 280–360px。 Market 快速改价 · 调整数量 · 备注 tag
Drawer 点行内按钮 或
点行本身		 字段多 / 需要看行详情 / 有预览计算（成交额、手续费、可得金额）。右侧滑出，列表仍可见、可切行。 Market 上架 / 调整挂单 · 平仓确认 · 订单详情 · 转账
Modal (Confirm) 点行内按钮 破坏性 / 不可逆 / 大额。没有表单，只有「确认吗？」。 撤单 · 删除挂单 · 卖出全部 · 退出队伍
Route 页 点行内按钮 多步流程、完整创建新对象、需要自己的 URL 可分享。 创建订单 /orders/new · Raid 配队 /raid/:id/lineup

详细组件规则见 §07 模态层。本节只管"列表行触发时怎么选"。

行内按钮的布局规则

  • 行末右侧，最多 2 个可见按钮 + 1 个 ⋯。再多就进 ⋯。
  • 样式：secondary · sm（28px 高）。主操作可以是 primary · sm，但一行最多 1 个 primary。
  • 顺序：次要 → 主要（主要最靠右，拇指/光标落点）。
  • 破坏性按钮单独放进 ⋯ 菜单末尾，不直接挂行上。
  • 按钮文字用动词：卖出 / 撤单 / 上架 / 领取——不写 详情 / 更多（整行已经可点进详情）。
  • 操作与行主内容之间留 16px 间隔；按钮之间 6px。
  • ⋯ 菜单永远在行末最右，32×32 hit area，点击展开（非 hover）。

行与容器的几条硬规则

✅ Do

  • 点整行 = 进详情（drawer 或 page）。
  • 点行内按钮 = 执行那个操作，不进详情。
  • Popover 锚定按钮，箭头指向触发点。
  • Drawer 打开时，当前行高亮（accent-tint 左边条 2px），让用户知道看的是哪一条。
  • 执行成功 → toast「已撤单 · 撤销」，5s 内可撤销（见 §10 toast · §09 L2）。
  • 异步操作：按钮上显示 spinner，禁用该行其他按钮，其他行不锁。

❌ Don't

  • 行内按钮点击后整行也响应跳转（事件冒泡炸）——stopPropagation 是必须的。
  • 把表单塞进行内 expand（手风琴展开）。列表是浏览，输入走 popover/drawer。
  • 把"改价"放 modal——打断浏览，看不到其他挂单。
  • 把"撤单"做成行内一键执行——破坏性操作必须 confirm。
  • 行里塞 >3 个按钮。
  • Hover 才出按钮——移动端无 hover，而且用户找按钮费劲。按钮常驻。

Popover 就地操作（1–2 字段）

  • 宽 280–360px，箭头指向触发按钮。自动翻转避开视口边界。
  • 标题 14/500，副标题一行描述"改什么"。
  • 底部操作条：左 secondary「取消」· 右 primary「保存」。Enter 提交。
  • 提交成功 → popover 关闭 + 行刷新为新值 + toast 确认。
  • 打开另一行的 popover 前，当前 popover 自动关。同屏只有一个。
  • 输入字段复用 §06 表单规范（mono、右对齐数字、inputmode）。

Drawer 详情 / 编辑（字段多或需要预览）

  • 从右侧滑出。宽 420px（桌面），移动端全屏从底部。
  • Drawer 里分区：对象头（图标 + 名 + ID）→ 状态块（关键数字）→ 表单（编辑区）→ 预览计算（手续费、可得金额）→ 底部粘顶操作条。
  • 列表行保持可见可点——点另一行切到那一行的 drawer 内容，drawer 不关、URL 的对象 key 切换。
  • URL 带 ?order=128473，deep link 可直接打开。关闭走 history.replaceState（见 §12）。
  • 内部可以再触发 confirm modal（平仓确认、撤单确认）——modal 盖在 drawer 之上。

Confirm Modal（破坏性 / 不可逆）

  • 只用于"确认吗？"——没有表单字段。有字段改走 drawer。
  • 危险级别和文案模板按 §09：L1 toast · L2 ConfirmDialog · L3 输入对象名 · L4 L3+强调金额。
  • 主按钮 variant="danger"。焦点默认在取消上。
  • 大额 / 一次性的"卖出全部持仓"→ 标题写金额："确认以 $12,400 撤下这张挂单？"

批量操作（多选 → 顶栏）

  • 行首有 checkbox。勾选 ≥1 行 → 表格顶部出现粘顶操作条：已选 3 条 · 批量撤单 · 批量下架 · 取消。
  • 条高 44px，bg-tertiary 背景，左文案右按钮。
  • 批量操作统一走 modal confirm："确认撤下 3 张挂单？" + 列出受影响对象（超过 5 条写 "等 N 条"）。
  • 异步：按钮显示 spinner + 进度「3/10 完成」。结束 → toast「成功 8 · 失败 2 · 查看」。点「查看」展开失败详情 drawer。
  • 批量跨页：只操作当前页。需要跨页时提示用户"仅选中当前页 25 条"。

异步反馈 · 一条统一流程

乐观更新 + toast + 可撤销
点击行内按钮 → 按钮显 spinner，该行其他按钮 disabled → 乐观：立即在 UI 上体现（行变灰 / 移除 / 状态改变） → 请求完成： 成功 → toast「已撤单 · 撤销」5s（见 §10） 失败 → 回滚 UI + toast「撤单失败 · 重试」（红），保留可重试按钮
  • "撤销"只在真正可撤销的动作上给（撤单 · 删除草稿）。不可逆的（支付成功、已发送）不给。
  • 5s 内点撤销 → 发出反向请求；超时 → fire & forget。
  • 状态变化要在行上先变，toast 只是确认；不要只靠 toast 告诉用户"成了"。

移动端

  • 行内按钮高度 ≥ 40px（命中目标）。一行最多 1 个可见按钮 + ⋯。
  • Popover 改为底部 action sheet（从底上推），内容一致。
  • Drawer 改为底部全屏 sheet。
  • 批量操作条置于屏幕底部（在 tabbar 之上），不吸顶。
  • 不用 hover；长按行 400ms 弹上下文菜单（等价 ⋯）。

Agent 自检

  • 这个按钮真的需要吗？它和"点整行进详情"重复了吗？
  • 我把表单塞进 modal 了吗？（字段 ≥ 3 → 改 drawer）
  • 危险操作有 confirm 吗？非危险操作被迫多点一下 confirm 吗？（两种都是错）
  • 异步操作 UI 先变了吗？还是只有 toast？
  • 移动端这行按钮还能点中吗？

表单

静态 label 在 input 上方。离焦才校验格式，键入不骚扰。

Field · 默认
4–20 字符，仅 ASCII 小写 + 数字 + 下划线。
Field · 错误
请输入有效邮箱，如 you@example.com。

校验时机

字段类型时机为什么
普通文本提交时键入期间不骚扰。
格式类（邮箱、URL、登录码）blur 时用户离开字段才知道是否合法。
强度类（密码）键入时实时反馈强度条。
字符计数键入时右下角显示 142 / 280。

提交流程

  1. 点提交 → 按钮立即禁用 + 变 loading（内部 12px spinner 替换 left icon，label 变 加载中...）。
  2. 成功 → toast + 跳转 / 关 modal。
  3. 失败 → 按钮恢复，toast (danger) + 字段级错误。
  4. Timeout 10s → 按钮恢复 + toast 连接错误，请重试。

规则

  • 必填：label 右侧 2px 红点。不用 *。
  • Placeholder 不能当 label 用。label 永远静态在上方。
  • 提交按钮禁用的唯一条件是「有必填为空」。其他一律可点（点后再显错）。
  • 单错误就地显示，多错误才加表顶 summary 卡。
  • 验证码：6 个 56×56 方块，逐格聚焦，粘贴自动填充。
  • 下拉：≤6 项用原生 <select>，>6 项用搜索下拉。

数值 & 金额输入

✓ 这样
<input type="text" inputmode="decimal">
移动端唤起带小数点和千分位的数字键盘，但仍是 text 字段，可解析后缀单位（K / M / B / 万 / 亿 / %），可粘贴带符号的字符串。
✕ 不要
<input type="number">
移动端弹出纯数字键盘（没小数点），吞后缀，吞千分位，滚轮意外改值，不同浏览器行为不一致。
  • 所有数值 / 金额输入一律用 type="text"，配合 inputmode 控制键盘。
  • 整数字段 inputmode="numeric"；带小数 inputmode="decimal"。
  • 视觉：金额输入 mono + 右对齐，前缀 $ / 后缀单位做成非交互 adornment，不进入 input value。
  • 支持后缀解析：键入 1.2M → 展示为 $1,200,000；5 万 → 50,000。blur 时格式化，focus 时还原为可编辑数字。
  • 允许粘贴 $1,284.25 / 1,284 / −500，parser 自动清洗千分位、货币符号、全角字符。
  • 禁用滚轮改值：onWheel={e => e.target.blur()} 或 CSS input[type=text] { -moz-appearance: textfield }。
  • 非法输入 不 在键入时阻止，blur 时校验 + 显示错误。让用户能自由键入、粘贴、撤销。

12 · Routing & URL

Routing & URL

URL 是唯一可分享、可刷新、可后退的状态容器。能写 URL 的状态就不走 state。

Route 结构

  • 扁平优先。/wallet /market /stocks。单用户产品，不套账号段。
  • 详情走子段：/stocks/:ticker · /pals/:id · /market/orders/:orderId。
  • 动态段用 slug 而非数字 ID：/pals/sparkbear-0042，不是 /pals/42。
  • 所有段小写 kebab-case：/trading-post，不是 /TradingPost。
  • 后台统一 prefix：/admin/...，进入需权限。

哪些状态进 URL

✓ 进 URL
  • 列表的 search / filter / sort / page
  • 当前 tab（?tab=overview）
  • 可 deep-link 的 drawer 对象（?order=128473）
  • Segmented 选择（?range=7d）
  • 日期 / 区间筛选
✕ 不进
  • Modal 开关（确认框、登录）
  • Tooltip / Popover
  • 临时 UI 态（hover、expand、collapse）
  • Loading / Skeleton 状态
  • 视觉偏好（密度、主题）— 走 localStorage

参数命名与格式

Example URL /market?search=fire&filter_status=active&sort=price:desc&page=3&tag=rare&tag=legendary&from=2026-04-01&to=2026-04-18
  • 键名小写 snake / kebab：sort · filter_status · page_size。
  • 排序：sort=<field>:<dir>，dir 是 asc/desc，默认省略。
  • 多值筛选：重复 key ?tag=rare&tag=fire。不用 CSV（跟逗号冲突）。
  • 布尔：存在即真。?archived == archived=true。
  • 日期永远 YYYY-MM-DD，不带时分秒。
  • 默认值不写 URL。第 1 页不写 page=1。URL 越短越好。
  • 不往 URL 塞 base64 / JSON。复杂到需要编码 → 改 named view（?view=my-watchlist）。

Deep link · 刷新 · 后退

  • 任一 URL 打开都应直接落到对应视图，不需要多一步点击。
  • 刷新不丢任何 URL 状态。任何 setState 却不写 URL 的筛选都是 bug。
  • 后退语义可预测：列表 → drawer → 后退 = 关 drawer；列表 → 子页 → 后退 = 回列表 + scroll 位置恢复。
  • history.scrollRestoration = 'manual' + 自己记录位置。
  • 多步 stepper 不每步写 URL，上一步 / 下一步 不产生 history 条目。

Drawer / Modal 的 URL 行为

覆盖层进 URL说明
ConfirmDialog（删除、退出）❌一次性决策，不 deep-linkable
Login modal❌改用 route /login，不是 modal-on-top
对象详情 drawer✅?order=128473，分享链接直达
移动端 filter drawer❌筛选本身进 URL，drawer 开关是 UI 态
创建表单 modal看长短长表单走 route /orders/new，短表单 modal 不进

Drawer 关闭时从 URL 移除 key，用 history.replaceState，不新增历史条目。

API 参数对齐

  • URL query 和 API query 用同一套键名。
  • 前端 /market?sort=price:desc&page=3 ↔ API GET /api/market?sort=price:desc&page=3。
  • 分页用 page + page_size（不用 limit/offset，难向用户解释）。
  • 返回元数据：{ items, page, page_size, total, total_pages }。
  • URL 控制在 2000 字符内，超了就是信号 → 改 server-side saved view。

15 · User Language

用户语言 vs 开发者语言

用户不需要知道你是怎么实现的。这是 Agent 最常犯的错——把字段名、状态枚举、技术术语直接渲染到界面上。

UI 里不该出现的东西

  • 技术值：null · undefined · NaN · [object Object]
  • HTTP 状态码：Error 500 · 404 Not Found · 422
  • 内部枚举：PENDING_APPROVAL · STATUS_ACTIVE
  • 数据库字段名：user_id · created_at · order_no
  • 调试标签：TODO · WIP · TBD · placeholder · coming soon
  • 技术堆栈词：endpoint · payload · timeout · webhook

翻译表

❌ 开发者写的✅ 用户看到的
